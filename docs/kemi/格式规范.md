# KemiCAD 自有文件格式规范（.kemi_*）

状态：P0 定稿（2026-10-26）。分支：`kemi-format`。

## 1. 目标

- KemiCAD 新保存的文件使用自有扩展名与自有根标记，官方 KiCad 打开时明确拒绝（不误读、不静默降级）。
- KemiCAD 继续完整读取旧的 `.kicad_*` 文件，并可显式导出为官方 KiCad 格式。
- 所有扩展名 / 根标记 / JSON 标记集中在一个格式档案（`include/kemi_format_profile.h`，命名空间 `KEMI_FORMAT`）中，禁止分散 `#ifdef` 与全局字符串替换。

## 2. 格式契约

| 文档 | 新扩展名 | 新根 / 标记 | 旧扩展名 / 旧根 |
|---|---|---|---|
| 工程 | `.kemi_pro` | JSON `"kemicad":{"format_version":1,"document_type":"project"}` | `.kicad_pro` |
| 工程本地状态 | `.kemi_prl` | JSON 标记，`document_type`=`project_local` | `.kicad_prl` |
| 作业集 | `.kemi_jobset` | JSON 标记，`document_type`=`jobset` | `.kicad_jobset` |
| 原理图 | `.kemi_sch` | `(kemi_sch (format_version 1) (version N) ...)` | `.kicad_sch` / `(kicad_sch` |
| PCB | `.kemi_pcb` | `(kemi_pcb (format_version 1) (version N) ...)` | `.kicad_pcb` / `(kicad_pcb` |
| 符号库 | `.kemi_sym` | `(kemi_symbol_lib (format_version 1) (version N) ...)` | `.kicad_sym` / `(kicad_symbol_lib` |
| 封装 | `.kemi_mod` | `(kemi_footprint "名称" (format_version 1) (version N) ...)` | `.kicad_mod` / `(footprint`、`(module` |
| 图框 | `.kemi_wks` | `(kemi_wks (format_version 1) (version N) ...)` | `.kicad_wks` / `(kicad_wks`、`(drawing_sheet`、`(page_layout` |
| 设计规则 | `.kemi_dru` | `(kemi_dru (format_version 1) (version 2) (rule ...) ...)` | `.kicad_dru` / 无包裹的 `(version 2) (rule ...)` |

说明：
- 嵌入的子块（板内 `(footprint ...)`、库内 `(symbol ...)` 等）不改名。
- `format_version` 是 KemiCAD 容器版本（当前 `FORMAT_VERSION=1`，可读下限 `MIN_FORMAT_VERSION=1`），与 KiCad 的 `(version YYYYMMDD)` 相互独立、两者都写。
- 读盘门禁（硬要求）：`.kemi_*` 必须带可识别的 Kemi 根/JSON `kemicad` 标记与整数 `format_version`；版本落在 `[MIN_FORMAT_VERSION, FORMAT_VERSION]` 才可读（范围内旧版可读）。高于软件上限必须拒读并提示升级；缺少标识/版本、标识或版本无法识别、低于下限一律拒读且不覆盖。官方 `.kicad_*` 不要求 Kemi 标记，继续走兼容路径。
- `.pretty`、`.kicad_symdir`、设计块目录不改名；目录内单个文件按上表区分。
- 库表类型 `KiCad`、`kicad-cli` 命令名、内部 API 名称不变。

## 3. 读取规则

1. 新扩展名必须是新根（或合法 JSON 标记），否则报错。
2. 旧扩展名走兼容路径，旧根、新根均接受（新根只可能由 KemiCAD 写出）。
3. 新扩展名里出现旧内容：报错，不静默接受，也不覆盖。
4. 未知 / 损坏 / 缺少 Kemi 标识或 `format_version` / 标识或版本无法识别 / `format_version` 低于 `MIN_FORMAT_VERSION` 或高于 `FORMAT_VERSION`：明确拒读并提示（高于上限须提示升级），文件标记为只读，不覆盖。支持范围内的旧版必须可读。
5. JSON 文档：存在标记时 `document_type` 必须匹配、`format_version` 必须落在支持区间；`.kemi_*` 必须有标记。官方 `.kicad_*` 无标记时仍可读（兼容路径）。

## 4. 写出规则

- 写出风味由目标路径决定（`KEMI_FORMAT::FlavorForPath`）：
  - `.kemi_*` → 新根 / 写入 JSON 标记；
  - `.kicad_*` → 官方 KiCad 根、不写标记（这就是“导出为官方 KiCad 格式”）；
  - 无路径（剪贴板、API 字符串）或其他扩展名 → 旧语法，保证片段与上游互通。
- v9/v10 降级导出器保持旧根不变。
- 文本统一 UTF-8。

## 5. 兼容矩阵

| 读取方 \ 文件 | 旧 `.kicad_*`（旧根） | 新 `.kemi_*`（新根） | `.kicad_*` 内含新根 | `.kemi_*` 内含旧根 |
|---|---|---|---|---|
| KemiCAD（本分支 P1 起） | 读取（兼容路径） | 读取 | 读取 | 报错，不覆盖 |
| KemiCAD（P1 之前的版本） | 读取 | 不识别扩展名 / 根报错 | 根报错 | 读取（旧行为） |
| 官方 KiCad 发行版（固定一个版本，P4 验证） | 读取 | 应拒绝（扩展名不在过滤器、根未知） | 应拒绝 | 不识别扩展名 |
| 官方 KiCad nightly（P4 验证） | 读取 | 应拒绝 | 应拒绝 | 不识别扩展名 |

JSON 文档：官方 KiCad 会忽略未知键 `kemicad`，因此“拒绝”依赖扩展名（`.kemi_pro` 不在其工程过滤器中），该项需 P4 实测确认。

## 6. 已批准的 9 项决定

1. JSON 文件只加标记（`kemicad` 对象），不改结构。
2. `.pretty`、`.kicad_symdir`、设计块目录不改名。
3. 旧工程首次保存为新格式时写入新目录，保留原工程。
4. 工程外的子图不改写，提示用户复制进工程。
5. 同名新旧文件并存时报告冲突，由用户选择。
6. 库表类型 `KiCad`、`kicad-cli`、内部 API 名称不变。
7. 提供导出为官方 KiCad 格式。
8. 用一个固定发行版 + 一个 nightly 验证官方 KiCad 拒绝新文件。
9. 本授权覆盖 rules.md 中关于格式 / 扩展名的禁令（仅限 `kemi-format` 分支）。
